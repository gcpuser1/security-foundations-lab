# 10 · Forensics and incident response (DFIR)

**Priority:** High (added) · **Effort:** ~3 week(s) · **Status:** not started

## Why this matters

When something goes wrong, someone has to work out exactly what happened. This is the security version of root-cause debugging.

## 1. Stumble first (before any reading)

Take a snapshot of one of your lab VMs, do a few ordinary things on it, then try to reconstruct exactly what you did from logs alone.

Write your guess in `notes.md` before you look anything up.

## 2. Concepts covered

- [ ] Incident response lifecycle
- [ ] Memory analysis
- [ ] Event log review and timelines
- [ ] File system, network and cloud forensics
- [ ] Evidence handling

## 3. Build yourself

Velociraptor and Volatility on your own lab VMs.

## 4. Practise on

Hack The Box Sherlocks.

## 5. Gate check

Rebuild an incident timeline from logs and memory alone.

Explain it to Claude with no notes. Don't start the next unit until you pass.
