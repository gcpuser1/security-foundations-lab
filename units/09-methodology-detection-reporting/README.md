# 09 · Methodology, detection and reporting

**Priority:** High · **Effort:** ~2 week(s) · **Status:** not started

## Why this matters

Skill without method doesn't scale. Defenders see attacks through logs, so seeing what they see sharpens root-cause thinking.

## 1. Stumble first (before any reading)

Pick one of your earlier lab write-ups. Ask: what would a defender's logs have shown at each step? Write it before reading about detection.

Write your guess in `notes.md` before you look anything up.

## 2. Concepts covered

- [ ] Recon, enumeration, chaining findings, reporting
- [ ] Logging pipelines and SIEMs
- [ ] MITRE ATT&CK as a shared language
- [ ] Writing a professional report

## 3. Build yourself

Ship your lab logs to an open-source SIEM such as Wazuh.

## 4. Practise on

Retired HTB or TryHackMe machines, plus one full written report.

## 5. Gate check

A professional report with findings mapped to MITRE ATT&CK.

Explain it to Claude with no notes. Don't start the next unit until you pass.

## Read and reference

- [MITRE ATT&CK](https://attack.mitre.org/)
- [Wazuh documentation](https://documentation.wazuh.com/)
